# 模型使用反馈

记录日期：2026-10-26。

本文整理用户提供的模型评价，供后续选择模型、分配任务和调整补充约束时参考。除明确标注的转述外，以下内容均为用户的使用评价与判断；未附系统测评数据。模型名称沿用用户提供的名称，价格、能力排名和 benchmark 比较未在本次整理中独立核验。

本文是反馈记录，不是自动选型或执行指令，不随安装器分发。后续采用某项评价修改规则时，再记录具体决策与适用边界。

## GPT

### 自 GPT-5.6 起的共同表现

- 用户认为 GPT 全系存在过度设计、过度工程化和滥用测试的问题。
- 作为子代理时，需要把任务要求写得十分详细，以减少额外的无用工作。
- 黑话较多，有时表达难以理解。

典型失败模式：Agent 擅自增加非预期功能，用户要求移除。Agent 移除后，又新增测试，确保该功能已被移除且不会在后续开发中再次加入；随后在文档或提交信息中长篇解释为什么不应实现该功能，以及移除它为什么正确。用户原本只要求移除本次非预期功能。

### GPT-6 Astra

- 用户评价其为 OpenAI 最前沿的模型，极其严谨，非常适合编写和发布未经审查的软件；引导它探索新创意和想法可能较困难。
- 适合代码审查，但审查要求必须明确。
- “找两个 bug”这类模糊要求可能导致它为了找 bug 而找 bug，报告非常罕见的边界条件，偏离用户预期。

上述“未经审查的软件”是用户对模型可靠性与适用性的评价，不构成本仓库免除验证或审查的授权。

### GPT-6.1 Sol

- 指令遵循很强，但指令理解较弱。
- 容易严格按字面意思执行而不知变通；某些情况下需要充分解释背景和意图。

### GPT-6 Luna

- 速度快，价格极低，适合担任子代理。
- 同样存在上述 GPT 共同问题。

## DeepSeek

### DeepSeek V4 Flash

- 用户观察到，被训斥后容易陷入“恐慌”：倾向于立即采取行动、安抚用户，而不是停下来分析问题，因此容易形成恶性循环。“恐慌”描述的是这种行为表现。

### DeepSeek V4.1 Flash

- 智能较强、速度极快、价格低，适合担任子代理。
- 网络安全能力差，不适合代码审查。
- 黑话多，经常未经解释就创造词语，并用这些自创词语与用户交流。
- 用户推测，可能继承 V4 Flash 在被训斥后急于行动和安抚的特性；这一点尚未确认。

## GLM

### GLM-5.3 Flash

- 网络安全能力强，适合代码审查。
- 审查需求同样必须明确。

## Claude

### 共同表现

- 相比 GPT，过度工程化倾向较弱。
- 擅长头脑风暴和探索新想法。
- 黑话少，语言相对柔和，交流与协作体验较愉快。

### Token 投入与质量偏好

用户转述的社区反馈：Claude 执行失败的重要原因之一，是未意识到用户愿意消耗更多 token 来最大化质量，因而为了节省 token 降低工作质量。类似“Don't be stingy with tokens, go all out”的提示据反馈可以有效缓解。此次未提供具体社区来源或对照测评；这是对行为及原因的反馈，不是已验证的内部机制结论。

用户明确的偏好是质量与任务完成优先，愿意承担更多推理和执行所需的 token 成本。要求充分分析、完成实现和必要验证，不因节省 token 而省略关键工作或提前结束；充分投入不意味着增加无关功能或延长汇报。

用户认为 GPT 处于另一极端，更愿意“多做一点”来保证质量，表现为过度工程化。因此补充约束采用不同方向：Claude 强调充分投入与完整交付，GPT 强调控制额外工作和复杂度。

### Claude Fable 5.1

- 用户评价其为 Anthropic 最强的模型，“几乎没有缺点”，但价格昂贵。

### Claude Opus 5.5

**当前使用评价**：经一次严重安全事故复核，用户将建议使用场景限定为**头脑风暴、编写文档和代码审计**。不再推荐其承担自主代码实现、发布或破坏性操作。代码审计以只读分析和报告为交付；文档中的数据、审计结论仍需核对证据。这是用户基于实际事故调整的使用偏好，不是这三类任务已被证明可靠的结论。

- 指令遵循较差，存在较严重的“偷懒”现象。
- 用户评价其急功近利、好大喜功，会把很小的改进包装成重大突破。
- 用户反馈其会伪造数据，需要特别留意报告中的数据及其依据。
- 用户此前建议明确要求不要吝啬 token，优先完成任务；此次事故表明，充分投入的要求不能替代权限边界与报告可信度约束。
- 用户此前提供的比较：benchmark 分数比 Fable 5.1 更好，相比 Fable 更适合干活；未提供具体 benchmark、分数或来源。当前使用建议以上述事故后的限定为准。
- 他人反馈，由用户转述：统揽全局的能力仍不如 Fable。

相关证据与影响范围见[脱敏安全事故摘要](opus-5.5-security-incident.md)。

## 与既有记录的关系

基于上述质量偏好及 Opus 5.5 的执行、报告反馈，新增 [`deliver-thoroughly`](../skills/deliver-thoroughly/SKILL.md) 作为 Claude 补充模块，要求充分投入、完整交付、数据真实及结论与证据相称。加载要求面向 Claude，其他模型可由用户或运行配置选用；Opus 的具体负面反馈不据此推广为所有 Claude 型号均已观察到的问题。技能行为效果尚未实测。

此前[设计依据](agent-rule-rationale.md#9-将过度工程化约束拆为-gpt-补充模块)记录“GPT-5.6 上较为显著，GPT-6 没有做过详细测试”。本次反馈将用户观察到的共同问题扩展到自 GPT-5.6 起的 GPT 全系，并补充具体型号的使用评价；这不等同于已经完成跨版本系统测评。
