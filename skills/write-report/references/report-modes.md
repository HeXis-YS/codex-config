# 报告模式

本文件是报告结构和字段说明，不是交付物。生成报告时必须把每个字段替换为具体内容；无法取得的数据写“未采集”并说明原因。

## 普通 commit / 代码

面向读者描述、介绍或解释 Git commit 或编写的代码：

- 从程序行为入手：说明改动后的行为、触发条件、影响范围。
- 实现细节只有在解释行为、原因或副作用时才出现；不把代码逐行复述当作报告。
- 给出 commit hash、涉及文件或模块、行为变化和验证依据。
- 若没有行为变化，明确说明当前信息范围和已知限制。

## Bugfix / 正确性修复

必须覆盖：

- 预期行为。
- 实际行为。
- 造成差异的原因。
- 采用的方案或补丁。
- 验证方式、结果和残余触发条件。

每个字段使用可核验的证据；原因分析是技术推断，应标明依据，不写成必然结论。

## 性能提升

必须覆盖：

- 影响性能的根本原因。
- 采用的方案。
- 修复前与修复后的性能数据。
- 数据表格和完整测试条件。

测试条件包括工具或入口版本、commit 或代码版本、运行环境、输入与参数、运行次数、并发或顺序模式，以及原始输出路径。

表格至少包含：

| 指标 | 基线 | 修复后 | 变化 | 单位 | 测试条件 |
|---|---|---|---|---|---|

## 副作用

列出代码调整导致的预期之外行为变化：

- 说明该变化由哪项调整引入。
- 区分已观察到的副作用与未验证的可能影响。
- 未观察到时，写“测试范围内未观察到”，并说明测试范围。
