# 写入 lessons.md

## 调用边界

- 仅在用户显式调用 `$write-lessons` 时执行；用户决定记录范围、等级和是否写入。

## 事故等级

按用户给出的等级记录；未给出时先询问，不自行推断或省略：

- A 级：代码进入生产环境，并造成了可审计的真实损失。
- B 级：代码被提交至上游或进入了生产环境，但被及时发现，未造成可审计的损失。
- C 级：agent 的失误、疏忽导致丢失本地工作进度、意外删除文件或破坏代码。
- D 级：agent 的失误、疏忽导致浪费了大量时间、金钱、token 等。
- E 级：失误尚未造成影响，但被用户观察到了明显的倾向并被纠正和记录。

## 记录要求

- 读取现有 `.codex/lessons.md`，避免重复；只按用户指定内容记录，不自行增删。
- 记录必须包含日期和事故等级，并覆盖事件经过、后果与影响、原因分析、总结教训。
- 用户未提供某一部分时先询问，不用推测、情绪或“用户纠正了我们”填充。
- 后果与影响按用户提供的事实记录；不得因“用户不满”或“用户纠正”单独推断可审计损失。
- 教训按用户要求写；默认可跨任务化，但如果用户明确要求记录具体对象或实例，按用户要求执行。

## 写入格式

从当前日期开始，新记录追加到文件末尾：

```markdown
## YYYY-MM-DD

### 事故等级

A / B / C / D / E

### 事件经过

...

### 后果与影响

...

### 原因分析

...

### 总结教训

...
```

- 每部分给出足以支持结论的事实，不用推测填充。
- 新记录追加到文件末尾，避免打乱已有记录；确需修订时说明改动范围并保留可追溯信息。
- `.codex/` 是本地工作流目录；除非用户明确要求，不纳入 Git 提交。

## 完成后

- 向用户确认等级、范围和措辞是否符合预期；记录内容由用户最终确认。
- 报告新增或修订的记录位置，不把记录本身当作提交内容。
