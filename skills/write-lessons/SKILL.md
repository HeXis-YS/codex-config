# 写入 lessons.md

## 适用与边界

- 用于把一次具备长期参考价值的失败、纠正、缺陷或验证偏差写成事故记录。
- 不用于：启动时阅读 lessons、把失败路径写入 todo、把一次性指令或用户观点直接转为经验。

## 先判断是否值得记录

- 读取现有 `.codex/lessons.md`，判断是否已有等价经验，避免重复。
- 新记录必须能支撑完整事故记录：日期、事件经过、后果与影响、原因分析、总结教训。任何一部分只能由猜测、情绪或“用户纠正了我们”支撑时，不记录。
- 后果必须可观察：例如浪费的时间、错误行为、数据或验证损失、需要返工或修复的代价；用户不满、反馈本身不作为后果。
- 原因分析必须基于实际证据；不能只复述用户指令、当前对象或本次错误。
- 教训必须能跨任务成立，提炼为原则、判定标准或方法；不记录只针对某个具体对象的规则。

## 写入格式

从当前日期开始，新记录追加到文件末尾：

```markdown
## YYYY-MM-DD

### 事件经过

...

### 后果与影响

...

### 原因分析

...

### 总结教训

...
```

- 每部分给出足以支持结论的事实，不用推测填充。
- 新记录追加到文件末尾，避免打乱已有记录；确需修订时说明改动范围并保留可追溯信息。
- `.codex/` 是本地工作流目录；除非用户明确要求，不纳入 Git 提交。

## 完成后

- 复核五个要素是否齐全、每部分是否有具体事实支撑、教训是否已泛化。
- 向用户报告新增或修订的记录位置，不把记录本身当作提交内容。
