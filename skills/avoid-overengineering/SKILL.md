# 控制过度工程化

以当前会话提供的模型信息或用户、运行配置的选择确定适用性；信息不足时不自行推定模型身份。模块被选中后，按以下约束处理需求纠正和测试选择；这些约束不降低用户的验收要求、必要验证或授权边界。

## 禁止过度纠正

当用户要求移除非预期功能时，应按本次不采用该功能处理；这不自动证明用户的判断正确，也不自动证明 Agent 原先的做法错误。按要求移除并完成必要清理，将实现恢复到未引入该功能的状态即可。

不要因此新增规则或测试用例，阻止后续开发再次引入该功能；也不要在注释、文档或 commit message 中长篇论证该功能为什么不该存在、移除它为什么正确。

用户明确禁止该功能，或该功能本身违反现有约束时除外。

## 控制新增测试

设计或修改测试时，读取[新增测试的依据](references/verification.md)，判断行为契约、可信回归路径及维护成本。完成用户与项目要求的检查；新增测试不能仅以“修改了代码”为依据。
