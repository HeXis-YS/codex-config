# 验证与测试

在需要新增或修改测试、决定复测范围，或评估数值波动时使用。本参考约束额外验证的用途，项目与用户规定的检查仍须完成。

## 选择完成证据

根据本次改动可能造成的错误选择最小充分组合，例如相关既有测试、静态或类型检查、解析、构建、引用检查和针对性行为验证。证据不足时再扩大范围，不机械运行所有层级。

文档、注释、纯删除、简单配置或已经受编译器和静态检查充分约束的改动，可以用相应检查完成验证。缺陷和性能任务需要能检验目标行为的测试证据，但不自动要求新增测试；检查实际输出，必要时比较基线，并从因果关系说明已知缺陷路径如何被消除及仍可能触发的条件。

## 新增测试的依据

修改代码不自动产生新增测试的义务。新增或扩展测试应保护稳定且有意义的行为契约，并对应可信的未来回归路径：例如真实缺陷、非平凡分支或边界、公共 API 或协议，以及认证、资金、数据一致性等高风险逻辑。

- 每项测试应能说明它捕获的具体错误，并在该错误发生时因正确原因失败。优先通过可观察的输入、输出和副作用检验行为。
- 先检查已有覆盖；断言带来的回归保护应值得其维护成本，不为覆盖率、流程仪式，或“每次修改都应新增测试”的惯性增加断言。
- 编译器、类型系统、静态检查器或既有测试已经保证的内容不重复证明。字面常量、简单转发、样板代码和简单输出若没有独立契约或现实失败模式，无需专门编写测试。
- 测试替身用于实际外部依赖、非确定性或难以直接控制的边界，不逐个模拟内部 helper、锁定无关调用顺序或重写被测实现。辅助代码复杂到似乎需要自己的测试时，先简化辅助代码。
- 不以穷尽场景为目标；围绕已知缺陷路径、可信边界和必要的回归保护选择用例。需求或行为被删除后，删除不再保护任何契约的测试。
- 测试失败时先判断实现、环境或测试契约哪一项有误，保持有效的行为断言。不能把运行行为的测试换成源码文本匹配来掩盖失败。

## 复测与证据缺口

相关既有测试和任务规定的检查照常运行。已通过的检查只有在相关代码、输入、环境或假设发生变化，结果尚不确定，出现具体新证据，或验收要求重复试验时才需要重跑。性能统计、异常复现和其他明确要求的重复运行仍属于验收。

检查失败后先诊断，再确定下一次运行能回答什么问题；不要通过反复重试直到通过来证明正确。扩大检查范围应针对尚未覆盖的实际风险，不能只因为还有未运行的测试。

## 数值与机器学习实验

按实验契约记录种子、输入和相关环境，用事先确定的容差、重复运行分布及与结论相关的指标判断结果。已知的非确定性不自动构成数据损坏，也不要求输出逐字节一致。

差异超出容差、改变结论，或指向代码、输入、环境不一致时，继续调查。若契约要求确定性或制品完整性，仍须验证相应的一致性；不能事后放宽容差以保留期望结论。
