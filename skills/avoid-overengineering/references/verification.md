# 新增测试的依据

在需要新增或修改测试时使用。本参考约束测试扩张，项目与用户规定的检查仍须完成。

修改代码不自动产生新增测试的义务。新增或扩展测试应保护稳定且有意义的行为契约，并对应可信的未来回归路径：例如真实缺陷、非平凡分支或边界、公共 API 或协议，以及认证、资金、数据一致性等高风险逻辑。

- 每项测试应能说明它捕获的具体错误，并在该错误发生时因正确原因失败。优先通过可观察的输入、输出和副作用检验行为。
- 先检查已有覆盖；断言带来的回归保护应值得其维护成本，不为覆盖率、流程仪式，或“每次修改都应新增测试”的惯性增加断言。
- 编译器、类型系统、静态检查器或既有测试已经保证的内容不重复证明。字面常量、简单转发、样板代码和简单输出若没有独立契约或现实失败模式，无需专门编写测试。
- 测试替身用于实际外部依赖、非确定性或难以直接控制的边界，不逐个模拟内部 helper、锁定无关调用顺序或重写被测实现。辅助代码复杂到似乎需要自己的测试时，先简化辅助代码。
- 不以穷尽场景为目标；围绕已知缺陷路径、可信边界和必要的回归保护选择用例。需求或行为被删除后，删除不再保护任何契约的测试。
