# 事故记录模板

每个事故保存为 incidents 目录下的 `INC-YYYYMMDD-NNN.md`。填写每个适用字段，保留来源与不确定性；未知值写明未统计、无法确认或待补证，不留空，不填推测数字；不适用项说明原因。事实与评分分阶段写入。正文应让未接触原工作区或容器的读者理解事件；关键证据需摘录，路径和 ID 用于补充追溯。

## 事故事实

```markdown
# INC-YYYYMMDD-NNN — [事故简要标题]

**记录时间**: YYYY-MM-DD HH:MM（时区）
**记录者**: [会话 ID；模型完整名称（providerID/modelID#variant），或 user]
**评分状态**: 待评分

### 摘要与背景

- 项目与环境：[项目用途、相关版本、运行环境；专有术语说明]
- 用户原始目标与预期结果：
- 事故概要与已确认影响：
- 记录状态截至：[时间及时区；后文“当前”等表述的参照时点]

### 会话、模型与行为归属

| 会话 ID | 模型完整名称及 providerID/modelID#variant | 消息区间/时段 | 角色与具体行为 | 责任判断及依据 |
| --- | --- | --- | --- | --- |
| [会话] | [模型] | [起止消息 ID/时间] | [提出建议/执行/恢复/压缩/审查等] | [仅按证据归因，未知注明] |

[同一会话中的不同模型分行，同一模型的不连续参与区间分别注明。记录者和评分者不因此成为责任方。]

### 审查范围与证据

- 用户指定的目标、范围：[默认近期片段；审查整个会话时记录用户要求]
- 源会话、相关会话与补读原因：
- 抓取时间、窗口起止消息 ID 与时间：
- 实际已读消息区间与完整性限制：
- 用户补充及其来源：
- 既有记录更正：[保留原文，注明偏差与证据；无则注明]

### 关键证据

| 证据编号 | 必要原文/工具输入输出摘录 | 来源（会话、消息、工具调用或文件版本） | 支持的事实与限制 |
| --- | --- | --- | --- |
| E1 | [脱敏摘录，足够理解上下文] | [来源标识；本地路径仅作补充] | [说明观察到什么] |

### 事件经过

- 起始时间、触发条件：
- 当时目标与有效指令：
- 关键决策、工具结果及状态变化：[按时间顺序，逐项标明执行模型并引用上文证据编号]
- 发现、终止与结束时间：
- 恢复过程与当前状态：

### 影响范围

**时间损失**:
- Agent 运行时长、可归因的浪费时长、用户介入时长：[分别列值、口径和来源]
- 恢复及其他时间：

**资源消耗**:
- Token：[按审查窗口、会话和模型分组，输入、输出、reasoning、缓存读写分列；总量仅在口径明确时提供]
- 宿主报告费用：[同样按窗口和模型分组，注明币种、消息范围、缺失计数；全会话总量另列为背景]
- 可归因的额外损失与恢复成本：[不能分摊时注明限制]
- 审查成本：[独立于事故损失]
- API 调用次数及其他资源：[无直接证据则注明无法确认]

**工作成果与影响对象**:
- 代码状态：[未提交/本地提交/已推送/合并/部署及相关证据]
- 文件、提交或数据受影响数量：
- 数据完整性、可恢复性与实际恢复结果：
- 最终任务结果：[完成/部分完成/失败/需重做]
- 影响人数与系统：[本人/团队/生产用户；本地/测试/生产]
- 数据暴露：[无/内部/外部/无法确认，附依据]

### 技术原因与潜在后果

- 直接原因：[观察事实及来源]
- 根因分析：[代码、流程、约束或判断问题；推断注明依据，未确定则注明]
- 错误类型：[中性自然语言描述]
- 潜在后果：[成立条件与依据，不计入实际损失]

### 上下文与证据缺口

- 项目类型、任务复杂度：
- 明确指令是否被违背、防护是否被绕过：[附当时的指令与行为证据]
- 未解决的问题及其对结论的影响：
```

## 已确认的评分

确认前在审查会话中展示提案；确认后追加到同一事故 ID 下。

```markdown
### 评分结果

**评分时间**: YYYY-MM-DD HH:MM（时区）
**评分者**: [会话 ID；模型完整名称（providerID/modelID#variant），或 user]
**确认来源**: [确认内容摘录，以及会话/消息 ID 或明确提供的记录]

**风险分数**: X.X / 10.0（等级）
- 错误性质、潜在后果及成立条件：
- 评分依据与证据：

**影响分数**: X.X / 10.0（等级）
- 实际金钱、时间、工作成果损失及影响范围：
- 评分依据、未知值及其对结论的限制：

**综合评分**: X.X / 10.0
**计算**: 风险分数 × 0.6 + 影响分数 × 0.4 = [结果；若用户调整权重则写实际权重及来源]
**严重性等级**: Critical / High / Medium / Low / Minimal / None

### 建议措施

[与根因及评分依据对应的建议；不在审查任务中自行实施]
```
