# 文体与用途

按当前任务阅读对应小节。这里提供组织信息的依据，不要求每份文本使用相同标题或包含所有栏目。

## 文档、操作指南与故障排查

- README 开头说明项目用途、适用读者和开始使用的入口，再安排安装、用法及限制。局部修改保持既有导航与链接有效。
- 概念说明先给定义和适用范围，再解释关系与取舍；用例子帮助读者理解，但不让示例中的值变成正式默认值。
- 操作指南在动作之前给出已知前提、必要输入和相关风险；按依赖顺序写动作，把关键预期结果放在动作之后，使读者知道是否可以继续。
- 根据来源写明分支和停止条件。必须同时发生的动作保留在一起，避免编号顺序制造串行含义。
- 故障排查从可观察现象开始，给出用于区分原因的检查及相应处理。证据不足时保留候选原因，避免把猜测写成诊断结果。
- 原有警告保持醒目并位于相关动作之前。新增警告需要具体风险依据；普通说明不套用警告模板。

## 设计说明、项目规则与 skill 文本

- 设计说明连接问题、约束、决策、依据和代价。已有决定与待选方案分清，结论的适用范围可追溯。
- 规则写清适用对象、触发条件、动作、例外和完成或停止条件。只写影响决策的要素，不为填满结构增加不存在的条件。
- 区分规范性要求、解释和示例。示例帮助解释规则；它不能暗中扩大适用范围、增加权限或改变义务。
- 同一契约保留一个权威位置，其他位置引用它。把维护依据与执行指令分开，避免两个版本产生冲突。
- 润色 `AGENTS.md`、`SKILL.md`、提示词时，对照修改前后的触发、默认行为、例外和停止条件。即使句子更短，也不能把有条件的建议变成无条件命令。

例：来源是“预计需要重复运行时，首次运行前保存入口；首次运行后才决定重跑时，第二次运行前保存。”可以分成两个条件分支呈现，不能缩成“重复运行时保存入口”，因为这会丢失保存时点。

## 代码注释与接口说明

- 阅读紧邻实现与必要调用契约，确认注释有依据。注释解释非显而易见的原因、约束、不变量和边界，不逐句翻译代码。
- 区分公共接口说明与实现注释。接口说明重点是调用者需要的输入、返回值、错误和副作用；实现注释重点是当前选择为何必要。
- 对兼容处理或绕行方案，写明要求它存在的条件；有已知 issue 或移除条件时引用。没有来源时不编造历史原因或删除期限。
- 保留 docstring、文档标记和项目注释格式。编辑范围是注释时，核对 diff 中可执行代码、注解及工具指令没有被意外修改。

例：代码中的 `delay *= 2` 本身已说明数值操作。只有上下文证实原因时，才写“每次重试将等待时间加倍，以降低持续失败时的请求频率”；不能从这一行推断它修复了某个未记录的生产事故。

## 技术报告与工作状态

- 先给出与报告问题对应的结论，再给证据、条件和限制。证据不足时缩小结论范围，或说明仍缺什么依据。
- 区分观察事实、技术推断、计划和建议。使用数据比较时，保持对象、单位、基线和测试条件可关联；测量与证据的完整性遵循报告任务的要求。
- 描述完成状态时，同时明确工作对象与验证范围。动作完成、检查通过、检查失败、已知未执行、记录缺失是不同事实。

| 已知情况 | 可以怎样写 | 不能据此推断 |
| --- | --- | --- |
| 只完成了文件修改 | “配置已修改；运行检查尚未执行。” | 整项验收已经通过。 |
| 某项检查实际失败 | “集成检查失败，错误见日志中的连接超时记录。” | 只是未验证。 |
| 明确知道未执行检查 | “未执行 Windows 检查，当前环境只有 Linux。” | Windows 检查失败。 |
| 来源中没有检查记录 | “现有材料无法确认是否检查过 Windows。” | 检查一定没有执行。 |
| 仅样本内观察到变化 | “在该样本与配置下，错误率降低。” | 所有输入上都有效。 |

这些是语义区别，不要求固定状态词或统一句式。写明实际证据；缺少记录时，不替来源编造执行情况或原因。

## 与用户交互及产品文字

- 回答先满足用户当前的信息需要，再补充支撑理解或决策的依据。状态更新说明已知结果、关键不确定性及下一步能解决什么问题。
- 用简短、可纠正的表述呈现对用户意图的理解，区分明确要求和影响判断的假设。遵守当前交互格式，避免用重复复述增加负担；表达理解不自动要求用户再次确认。
- 需要澄清时，指出缺失的信息以及它会改变的决定。只询问当前不能自行确认、且确实影响交付的内容。
- 保持直接、尊重的语气，去掉空泛赞美、夸张承诺和无信息量的结尾。用具体结论与证据说明进展。
- 报错或帮助文字说明失败操作、相关对象和用户能够执行的处理方法；只有已知可行时才给恢复动作。保持界面篇幅与产品术语约定，必要的技术细节服务于用户决定。
- 对话中的任务解释、意图核对和审校说明放在交付正文之外；用户要求纯文本成稿时，交付约定范围内的成稿。
