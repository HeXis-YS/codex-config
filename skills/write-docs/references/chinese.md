# 中文表达

用于中文正文及混合语言文档中的中文段落。与 `SKILL.md` 的语义保真要求配合使用。

## 动作、主语与指代

- 用直接动词：“检查配置”“安装依赖”，省去“对配置进行检查”“开展依赖安装工作”中的空转表达。
- 系统行为与读者动作分开写：“服务读取配置”与“运行启动命令”。上下文已经明确执行者时，不为补主语而重复“用户需要”或“系统将会”。
- 操作条件先于依赖它的动作，例如“如果校验失败，停止导入”。保留条件的逻辑方向；“只有校验通过才允许导入”不自动变成“校验通过后立即导入”。
- “其”“该”“它”“上述”等有多个可能指向时，写出具体对象；指代唯一时可保留自然衔接。
- 拆开层层嵌套的定语，保留限定关系。多个否定容易误读时，先确认逻辑再改写，不直接删除否定词。

## 术语与语气强度

- 优先沿用项目术语；需要解释的术语首次出现时给出中文名、英文或缩写，之后保持同一写法。没有准确通行译名时保留英文并说明含义。
- 区分“必须”“建议”“允许”“能够”“可能”的语义。“应”“可以”等词有歧义时，根据来源确认是义务、建议、许可还是能力，再决定措辞。
- “启用功能”“启动进程”“打开文件”可以减少歧义，但界面标签和项目专名保持原样；不要为了统一动词而改写标签。
- 对“优化”“提升”“完善”等说法，写出具体变化及依据。没有测量结果时，描述改动机制或预期目的，不补造收益。

## 数字、时间与排版

- 保留数值的精度与约数属性。“大概 5 秒左右”可写为“约 5 秒”，不能写成精确的“5 秒”。
- “以上”“以内”等边界会影响操作时，依据来源明确为“大于”“不小于”“不超过”或直接保留比较式；来源没有确定端点时，不擅自选定。
- 区分百分比变化与百分点变化。例如错误率从 4% 降到 3%，可写“下降 1 个百分点”或“相对下降 25%”；写明采用哪种口径。
- 长期文档中的相对日期有明确参照时可换为绝对日期，跨时区场景标明已知时区。没有依据时保留不确定性或求证，不把“尽快”改成自定期限。
- 沿用项目的标点与空格约定。没有约定时，中文正文用中文标点，中文与英文单词或阿拉伯数字之间留空格；数值与拉丁单位之间留空格，百分号紧接数值。代码、URL 和标识符内部保持原样。
- 界面文字与界面一致，并用引号、粗体等现有约定标明；引用中的标点和拼写按引用要求保留。

## 审校示例

以下只展示语言处理，示例事实不适用于其他项目。

| 来源或问题 | 处理方式 | 保留的边界 |
| --- | --- | --- |
| “缓存未命中时，响应大概需要 5 秒左右。” | “缓存未命中时，响应约需 5 秒。” | 条件与约数都保留。 |
| “建议每周备份一次。” | 原句已经清楚，可以保留。 | 建议不升级为强制操作。 |
| “客户端收到服务端的重试通知后，它会关闭连接。” | 查明关闭连接的一方后再改写。 | 不猜测“它”的执行者。 |
| “尽快重启服务。” | 若时限影响执行，询问允许的时限；否则保留原有紧迫性。 | 不生成来源没有的截止时间。 |
| “仅在令牌过期时刷新，访客请求除外。” | “仅在令牌过期时刷新令牌。访客请求不刷新令牌。” | “仅在”与访客例外仍约束同一动作。 |

以读者是否会误解为拆句依据。规则、报告、注释和对话的长度需求不同，不为达到字数目标而切断因果或条件。
