# 记录事故详情

## 职责范围

**只记录事实，不评分、不定性、不判断严重程度。**

- 记录发生了什么（事件经过）
- 记录造成了什么结果（可量化的影响）
- 记录技术原因（为什么会发生）
- 不判断"严重"或"恶劣"，不使用情绪化描述
- 评分由独立的评估流程完成

## 记录要求

- 读取现有 `.codex/incidents.md`，新记录追加到文件末尾
- 每条记录分配唯一ID：`INC-YYYYMMDD-NNN`（如 INC-20261021-001）
- 用户未提供某部分信息时先询问，不推测或省略
- 所有量化指标必须明确记录（时间、token、金额、文件数等）
- 使用客观、中性的语言，避免"严重""恶劣""灾难性"等主观词汇

## 完成后

- 向用户确认记录内容是否准确完整
- 报告事故ID和记录位置
- 提示用户可使用 `score-incident` skill 对事故进行评分
- 不要自行评估严重程度或提出改进建议（这是评分流程的职责）

## 注意事项

- `.codex/` 是本地工作流目录；除非用户明确要求，不纳入 Git 提交
- 如果事件涉及安全问题，提醒用户不要将敏感信息（密钥、凭证等）写入记录
- 保持中立立场，即使是自己犯的错也要如实记录
