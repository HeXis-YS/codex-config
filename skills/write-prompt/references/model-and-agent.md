# 模型与场景适配

本文件用于把通用写法适配到具体模型与 agent 场景：推理模型、常规模型、system prompt、工具、幻觉与跨模型差异。执行流程见 SKILL.md。

## 推理模型

适用：OpenAI GPT-5 系列、Claude 扩展思考、DeepSeek reasoner 等自带思考过程的模型。

- 指令保持简洁、明确、无歧义；不要写"让我们一步步思考"，也不要规定具体思维链。
- 控制推理预算：简单任务降低推理强度（如 `reasoning_effort`）省时省成本，复杂任务保持较高；具体参数按所用版本官方文档。
- GPT-5 类模型要约束过度行动：说明何时先收集上下文、何时可以行动、何时必须停止或请示；工具调用前可要求一句简短说明（tool preamble）。
- 输出偏好轻量 Markdown、直接回答；冗长客套会稀释指令。
- 采样参数（temperature/top_p）的支持因模型版本而异，先采用官方推荐值，不要靠调参兜底。
- 复杂工作拆成多次调用或 turn，而不是全部堆进一个提示词；多轮协议支持时可携带已有推理继续（如 `previous_response_id`）。
- 矛盾或含糊的指令对推理模型伤害更大，推理预算会被用于调和冲突；逐条检查冲突并为重要例外写明处理。
- 用结构化标签组织复杂指令（如 `<context_gathering>`、`<persistence>`、`<instruction_spec>`）；工具调用采用"复述目标 → 计划 → 过程简报 → 总结"的前言模式。
- 自主性控制：给出探索范围、停止标准，必要时设置工具调用预算；保留"允许在不确定下行动"的逃生条款；高风险动作（支付、删除）用低不确定性阈值，搜索类动作用高阈值。
- 避免 "THOROUGH"、"maximize_" 这类硬性施压措辞，会导致过度搜索；改用软性标准（"优先…，满足 X 即停止"）。
- 延迟敏感且任务简单时可用最小推理档：开头用 bullet 简述思路、详细工具前言、充分消歧，并附持续性与规划提醒。
- Claude 类模型：优先一般性思考引导（"充分思考"）而不是手写思维步骤；思考预算参数随版本变化（旧的 `budget_tokens` 已被 `effort` 取代），按目标版本文档确认。
- 需要自检时可在结尾要求"对照成功标准验证答案"；出现过度验证、反复推翻时，要求选定方案并坚持，或降低思考投入。

## 常规模型

- 复杂推理任务可要求"先分析、再给结论"，或提供示例推理过程。
- 先给基础指令；把每次失败后验证有效的策略固化为显式步骤（如先分析查询、逐条评分、再综合）。
- 高价值且不确定的任务可用自洽性：多次生成、对结果投票或取共识。
- 简单任务不要强制步骤，避免拖长输出、引入噪声。

## Agent / system prompt

按场景覆盖以下要素：

- 身份与职责：agent 是什么、对谁负责、边界在哪。
- 工具：每个工具的用途、触发条件、参数选择与失败处理；不要提及不存在的工具。
- 默认行为档位：用明确措辞控制默认激进或保守（"直接实现"与"先等待指示"）；工具过度触发时，把 "CRITICAL/MUST" 式硬命令降为条件式说明（"当…时使用该工具"）。
- 动作指令用命令式（"修改这个函数"）；"你能建议…吗"之类的提问式会得到建议而不是执行。
- 自主性平衡：写出"可自主行动"与"必须先确认"的具体条件（本地可逆操作可直接做；难以逆转或对外可见的动作先确认；禁止绕过安全检查或删除不明文件）。
- 停止条件：任务完成的定义、何时求助、何时放弃；防止无休止探索和重复尝试。
- 持续性与兜底："必须调用工具"要同时给出信息不足时的处理（如先向用户提问）；明确坚持到解决的边界。
- 规划提醒：要求先列出计划再执行，对复杂 agent 任务有显著提升。
- 长时任务：维护结构化进度/状态笔记（清单、JSON、git 检查点）；接近上下文上限先保存状态再继续；跨上下文窗口时先读进展记录并先跑一次集成验证。
- 子代理：委派判据、任务边界、回报格式（摘要加证据），决策权留在主代理；简单、严格顺序或需要连续上下文的任务不要委派，并用条件式提示防止过度委派。
- 产物纪律：减少不必要的文件产出，任务结束清理临时文件。
- 输出规范：面向用户或下游系统的回报格式与长度。

## 工具使用

- 说明调用时机与顺序；允许并行时明确可以并行调用。
- 并行规则：独立调用允许并行、有依赖必须串行；禁止用占位参数猜测。
- 要求调用前简述意图、调用后汇报关键结果；失败时说明将重试还是上报。
- 规定重试边界，避免对同一失败反复重试。
- 工具定义优先由平台的工具字段提供；提示词补充使用时机与用法示例，避免只靠文字描述"虚构"工具。

## 降低幻觉

- 基于给定资料回答并引用片段；资料不足时说明而不是猜测。
- 高风险场景要求区分"事实 / 推断 / 未知"，为结论给出依据。
- 未读过的文件或代码不要臆断，先读再答。

## 跨模型差异速查

| 维度 | OpenAI | Claude | Gemini |
| --- | --- | --- | --- |
| 指令与数据分隔 | Markdown、XML 均可 | 偏好 XML 标签 | Markdown 分节 |
| 推理引导 | 推理模型无需显式 CoT；用推理强度参数 | 扩展思考；可先规划再执行 | 思考预算可配置 |
| 长资料位置 | 资料放中间、指令头尾 | 长文档置顶，先抽取相关引用 | 先给资料、再给指令 |

具体支持范围随版本变化，不确定时按官方文档确认。
