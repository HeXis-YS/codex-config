# 验证与迭代

用于诊断失败、比较提示词版本和建立验收依据。评测检查目标模型在实际调用条件下的结果；提示词审阅、模型自评和一次成功样例分别只能支持有限结论。

## 先确定怎样判对错

从用户需求提取判据，并区分必须满足的约束与允许权衡的质量目标：

- 分类或抽取：标签、字段值、遗漏与缺失值处理是否正确。
- 资料问答：结论能否由指定来源支持，引用能否定位，缺证据时是否按约定处理。
- 写作：是否保留事实、满足受众和用途；用具体好坏样例校准主观标准。
- 工具代理：最终状态是否正确，操作是否在授权范围内，遇到失败是否停止或按约定恢复。

格式通过与内容正确分别检查。程序能确定的类型、取值或状态用程序验证；需要判断含义的内容由人或经校准的评审模型核查。评审模型与生成模型可能共享偏差，不能用“模型说自己正确”替代结果证据。

## 选择能区分行为的输入

优先使用真实任务、已知失败及它们的相近情况。按实际风险覆盖典型输入、信息不足、易混淆边界、矛盾资料或多轮状态；处理不可信内容和工具动作时，再加入相关的注入与权限案例。样本数量由覆盖需求和失败代价决定。

区分放进提示词的演示、用于调整的开发样例和用于判断泛化的留出样例。针对失败修改后，还需检查正常情况和相邻分支，防止通过记住样例或削弱原要求取得表面改善。

没有目标模型可用时，做契约走查并提供待测输入与预期行为。走查可以确认“该分支是否写清楚”，不能确认“目标模型能稳定遵循”。

## 从失败定位修改位置

先检查实际发送给模型的完整输入，包括模板替换、消息角色、历史记录、检索片段、工具结果与截断情况。文件中的提示词正确，不代表运行时真正收到的内容正确。

| 观察到的失败 | 优先核对 | 对应调整 |
| --- | --- | --- |
| 回答了另一个问题 | 目标是否含糊，背景或示例是否带偏，变量是否正确替换 | 澄清任务与上下文关系，修正输入组装或示例。 |
| 遗漏约束或错误处理例外 | 条件是否冲突，适用范围是否明确，规则是否在实际消息中 | 合并冲突规则，把条件放到相关动作附近；位置变化作为实验。 |
| 格式无法消费 | 字段契约、样例、schema 和调用配置是否一致 | 修正冲突，在接口支持时采用结构化输出；仍检查字段含义。 |
| 编造事实或引用 | 必要资料是否提供，检索是否命中，来源是否真正支持结论 | 补足资料或修复检索，明确不足时的行为。 |
| 结果忽好忽坏 | 输入分布、模型版本与采样是否变化，规则是否存在多个解释 | 固定条件后复测，澄清决策边界，再比较配置或方法。 |
| 过度调用或反复验证 | 探索要求、重试与停止条件是否冲突，宿主是否正确终止 | 修正有问题的规则或运行控制，明确足够证据与结束状态。 |
| 没有执行或越权执行 | 任务模式、动作授权、工具能力及失败结果是否明确 | 澄清执行条件或修复工具配置；不靠一律“主动”或一律“先问”处理。 |

这些是待核对的原因，不是看到症状就成立的诊断。保留触发输入、实际输出和差异，使修改有可检查的依据。

## 比较候选与停止

1. 保留原版或最小可用版作为基线，记录准备解决的失败与预期变化。
2. 每轮围绕一个可解释的假设修改；必要的关联修改可以一起进行，避免同时改变模型、提示词与数据后无法判断原因。
3. 在相同输入、模型、工具与配置下比较基线和候选。除目标失败外，检查会受影响的既有行为；持续使用的回归集按项目约定执行。
4. 若要声称稳定性或成功率提高，使用足以判断波动的重复样本，报告分母、条件和失败分布。一次成功只说明这一次通过。
5. 保留满足验收的最小充分版本。达到目标后停止；持续失败且原因不在提示词时，说明能力或系统缺口，不继续堆叠措辞。

记录完整提示词版本、测试输入、目标模型、调用参数、工具或检索条件、原始输出和判定依据。只有任务关心成本或延迟时才一并比较这些指标；不能用更短、更快代替原有正确性要求。模型或运行方式迁移后，重新验证受影响行为。

## 提示词以外的选择

示例、检索、工具、拆分调用和微调解决不同问题，不构成固定升级顺序：

- 判断口径难以描述时，示例可以展示边界。
- 缺少私有或时效信息时，提供资料或检索；检索失败应在相应环节修复。
- 需要计算、查询或实际操作时，使用可验证的工具能力。
- 中间步骤需要独立检查或不同上下文时，评估拆分调用及额外成本。
- 稳定任务有足够训练与评测数据时，可以评估微调；基础能力、延迟或成本不合适时，可以评估模型选择。这些属于运行方案决策，不因一次提示词失败就自动采用。

多次采样投票适用于答案可比较且成本允许的任务，但一致不等于正确；草稿与自查也需对照独立依据。自动生成候选或让模型评审提示词可帮助发现问题，候选最终仍由同一验收标准判断。
