# 迭代、验证与选型

本文件用于提示词写好后的测试、失败定位与升级决策。执行流程见 SKILL.md。

## 先定义成功标准

- 动笔前先确定：成功输出是什么样、如何判断（人工核查 / 自动指标 / 对照）、失败代价大小。
- 准备 3–10 个代表性输入，包含 1–2 个边界或对抗样例，固定下来作为回归集。

## 迭代循环

1. 记录当前版本与失败样例：输入、实际输出、期望差异。
2. 归类失败原因，再决定改哪里：
   - 任务理解偏：澄清目标，补充上下文或示例。
   - 约束遗漏：把要求前置，并在结尾重申。
   - 格式不稳：显式格式 + 示例 +（可行时）结构化输出能力。
   - 输出随机：降低随机性、增加约束，或使用自洽性。
   - 知识错误：提供资料、检索或工具，而不是改措辞。
3. 一次只改一类内容；改后重跑全部样例，防止回归。
- 卡住时：同义改写、换成等价任务形式（如改成多选题）、调整输入顺序。

## 升级路径

零样本 → 少量示例 → 检索 / 工具 → 微调。

- 缺知识：优先检索、工具或直接提供资料。
- 格式、风格或行为固定不下来：先加示例；仍不稳定再评估微调。
- 微调是最后手段：只有提示词空间用尽、且行为需要长期稳定时才采用，并说明维护成本。
- 提示词之外：延迟、成本或基础能力不足有时应通过更换模型、拆分任务或引入缓存/检索解决，而不是继续堆提示词。

## 参数

- temperature / top_p：事实、抽取、分类用低温（0–0.2）；创意发散用中高温（约 0.7）；两者只调其一；推理模型与较新模型先保持官方默认再实验。
- max tokens 是硬截断，长度控制优先写进指令并留足空间；可用 stop 序列限定结束位置。
- 结构化输出优先使用模型或平台提供的结构化输出能力，而不是只靠提示词约束。

## 常用模式速查

- 多步推理：逐步推理或链式调用（一步一验证）。
- 高不确定性：自洽性（多次采样、投票或取共识）。
- 缺外部信息：检索增强（RAG）或工具调用。
- 需要边推理边行动：ReAct 式交替，或先探索后收敛。
- 流程固定：分步指令加中间产物校验。
- 高质量长输出：草稿 → 对照成功标准自查 → 修订；保留中间产物便于检查。

## 提示词管理

- 提示词与代码一起版本管理；每次改动说明原因与观察到的效果。
- 保留一组"输入-输出"证据，便于对比与回滚。
- 把提示词当作代码管理：类型化存放、评审、测试、部署；重大评测前固定模型版本，避免模型更新干扰对比。
- metaprompting：把失败样例和当前提示词交给模型，让它指出应增删的短语与矛盾点；必要时生成多个候选并按评测集选优。
- 技法与模型版本相关；跨模型或跨版本复用前，先用小型评测集复验。
