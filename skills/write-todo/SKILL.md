# 写 / 更新 todo.md

## 先核对当前状态

- 读取现有 `.codex/todo.md`，并核对当前 Plan、用户最新指令、Git 状态和与任务相关的文件或运行记录。
- 文件不存在时创建新条目；文件已存在时保留所有既有任务记录，只处理当前正在进行的任务。
- 不把其他任务（包括已完成任务）的记录删除、覆盖、清空或修改。

## 记录内容

- 当前活动任务至少包含：目标与验收标准、状态、已完成与剩余工作、唯一下一动作、关键决策与假设、证据及产物路径、阻塞、已证伪路径、工作区或提交状态。
- 状态、下一动作、决策、证据、阻塞或失败路径变化后及时更新。
- 已完成的工作（含子项）立即标记为已完成，并补充结果、验证或产物。
- 在暂停、交接、长时间操作或预计上下文压缩前，确保记录是最新的。

## 条目结构

- 新条目沿用现有文件的风格；没有现有文件时，从 `## 任务：<名称>` 开始，并依次记录状态、更新时间、目标与验收标准、已完成、剩余、下一动作、关键决策与假设、证据与产物、阻塞、已证伪路径、工作区或提交状态。

## 写入纪律

- 禁止使用 `cp`、`mv`、`rm` 等可能覆盖、删除或清空文件的命令操作 `.codex/todo.md`。
- 只能增量追加新任务记录，或精确编辑当前正在进行的任务记录。
- 禁止删除、覆盖、清空内容，也禁止修改其他任务记录。
- 只有用户有权清理历史记录。
- `.codex/` 是本地工作流目录；除非用户明确要求，不纳入 Git 提交。

## 充分性检查

- 写入后确认：一个不了解先前对话的新 Agent 结合 Memory 和当前工作区，能回答目标、已完成、剩余、下一步、为什么以及哪些路径不能再试。
- 失败路径记录包含失败证据或原因、适用范围和允许重试的条件；证据记录来源或路径，不写无法核验的结论。

## 恢复流程

- 新会话、上下文恢复或接手时，先读取 `.codex/todo.md` 和 `.codex/lessons.md`。
- 与用户最新指令、Git 状态、文件内容、运行记录及仍在执行的进程核对。
- 观察事实优先于 todo，todo 优先于 Memory。
- 根据剩余工作重建或更新 Plan，从唯一下一动作继续。
- 不重复已完成步骤，也不重试已证伪路径，除非原证据失效或记录的重试条件已经满足。

## 完成与保留

- 任务完成时，将当前任务标记为已完成，并记录验证、提交、剩余风险和简短复盘。
- 已完成记录默认保留；新任务追加新条目。
- 完成后报告新增或更新的记录位置；记录本身不提交到 Git。
