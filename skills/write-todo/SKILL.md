# 保存任务交接

让未参与先前对话的接手者，根据笔记和当前工作区继续任务。会话内的步骤与进度交给可用的计划工具；交接笔记只保存恢复所需状态。

## 定位与写入时机

- 先按任务标题和状态定位当前条目，再读取该条目及直接相关的证据。文件不存在时新建；没有本任务条目时追加。不要为更新一项任务通读历史。
- 在预计跨会话、交接、暂停或需要持久检查点时保存。关键决定、授权边界、失败路径或阻塞若无法从现有计划和工作区恢复，也应及时记入。
- 更新只针对会影响接手的变化。步骤完成不自动要求写笔记，不复制整份会话计划；上下文压缩仅在恢复依据可能丢失时需要保存快照。
- 核对用户最新指令与实际工作区、提交、进程和日志。沿用既有任务标识，不把旧记录中的计划当作已经完成的事实。

## 内容与格式

每个任务使用一个二级标题和简短字段。目标、当前状态、唯一下一动作、工作区与证据位置应能直接定位；其他字段按恢复需要保留，不为填满模板写重复的“无”。

```markdown
## 任务：<稳定且可辨认的名称>

状态：<进行中 / 待接手 / 阻塞 / 已完成>
更新时间：<YYYY-MM-DD>

目标与验收：<预期结果与完成条件>
范围与授权：<接手者必须知道的边界和已确认决定>
当前状态：<已完成的关键结果，以及剩余工作>
唯一下一步：<一个可执行动作；阻塞时写解除条件，完成时写无>
工作区与证据：<分支或 worktree、提交或未提交改动归属、产物与日志路径>
关键决定：<选择及依据；未证实的假设明确标注>
阻塞与失败路径：<证据、适用范围、允许重试的条件>
```

剩余工作需要逐项辨认时可用简短 task list，不要求复制全部执行步骤。日志保存原始输出，笔记保存结论和可定位路径；不记录凭据或无关对话。

## 写入保护

- 仅追加新任务或精确更新当前任务，不覆盖整个文件；禁止使用 `cp`、`mv`、`rm` 操作该笔记，不删除、清空或改动其他任务及已完成记录。历史由用户清理。
- 当前任务从进行中转为完成时，记录最终验证、提交状态和实际剩余限制，然后保留条目。不要为了统一格式改写已有历史。

## 充分性检查

写入后确认：接手者无需依赖先前对话或 Memory，就能确定要完成什么、已做什么、下一步是什么、哪些内容必须保留，以及哪些失败路径不能直接重试。核对笔记没有把建议写成授权、把修改完成写成验证通过。

## 完成后

- 报告新增或更新的记录位置。
