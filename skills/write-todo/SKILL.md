# 维护跨会话状态

维护供跨会话恢复使用的当前状态文件，使未参与先前对话的新会话能够结合当前工作区直接接手。状态文件不是任务日志或完成历史；会话内的日常计划、进度与子任务交接利用会话上下文维护，不逐步写入文件。

## 路径与动作判定

- 默认路径为项目目录下的 `.opencode/todo.md`；用户或项目另有明确路径约定时按指定路径执行。`.opencode/` 下的本地工作记录默认不提交到 Git，除非用户明确要求。
- **保存或更新状态**（用户要求记录交接状态，或在已有任务上下文的会话中仅调用 `$write-todo`）：核对当前指令、工作区、运行记录与验证证据，创建、原位更新或收敛状态文件，完成后报告文件路径与记录摘要，不借机额外推进未要求的任务步骤。
- **按状态文件接续**（用户明确要求依据状态文件恢复或继续工作）：读取目标状态文件，按「接续核对」校验后从尚未完成的下一动作继续。若在新会话中仅调用 `$write-todo` 而未说明是记录还是恢复：目标文件存在时先读取并报告核对后的当前状态与下一动作，存在范围或授权未决项时等待用户确认；目标文件不存在且缺少任务上下文时，先询问要记录的内容或状态文件路径。

## 记录内容

状态应让新会话无需先前对话即可确定目标与验收、范围与授权、当前结果、剩余工作、阻塞和唯一下一动作，并能直接定位工作区及必要证据：

```markdown
# <稳定且可辨认的任务名称>

- **状态**：<进行中 / 待接手 / 阻塞 / 已完成>
- **目标与验收**：<预期结果与完成判据>
- **范围与授权**：<接手者必须遵守的边界与已确认决定；不把建议或推测写成授权>
- **当前结果**：<仍影响下一步的关键结论与证据位置>
- **阻塞与失败路径**：<当前阻塞、已证伪路径、证据、适用范围及允许重试的条件；无则省略>
- **下一动作**：<一个明确的可执行动作；阻塞时写解除条件，已完成时写无>
- **工作区与证据**：<分支或 worktree、提交或未提交改动归属、运行记录与产物路径>

## 待办

- [ ] <剩余待办及其前置依赖；仅列未完成项，不逐项记录工具调用>
```

按实际恢复需要保留字段，不为填满模板写重复的“无”，也不写入凭据或无关对话摘录。详细经过与原始输出留在会话、Git 或运行记录中，不把完成修改写成已通过验证。

## 原位更新、收敛与保护

- 文件已存在时先读取，核对其中记录的任务归属与完成状态，再用精确补丁将相关内容更新为当前状态。
- 更新同一任务时删除已失效描述和已完成待办，不按时间追加执行过程、旧方案或多版总结；仍影响下一步的已完成结果压缩为结论与证据位置。
- 任务已完成时，将状态收敛为完成结论、验收证据位置和提交状态，移除逐步待办清单。
- 记录新任务时，可直接替换已确认完成的旧任务内容，不累积历史任务；**不得因切换任务而覆盖尚未完成、仍需接续或其他会话正在维护的内容**，并存时保留各自恢复所需状态，归属不明时先求证。
- 整理或替换状态文件不包含删除其引用的证据、产物或其他工作区内容的授权。

## 接续核对

- 读取状态文件后，以用户最新指令确定目标与授权，以 Git、文件、运行记录及进程状态核对可能变化且影响下一步的事实；**可观察事实优先于状态文件**，不能以文件中的旧计划代替当前指令。
- 已完成状态不作为继续执行的任务；复选框或完成声明不能替代实际验收证据。发现状态文件过时时先原位修正。
- 从尚未完成的下一动作继续；不重复仍有效的已完成验证，不重试已记录的证伪路径，除非原证据失效或重试条件已满足。依据不足或证据冲突时，再定向查阅直接相关的历史。
